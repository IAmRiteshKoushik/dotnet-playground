Lesson 5 · 25 minutes

Make the framework behavior you already use visible.

You have a functional API. This final foundation lesson explains why a handler can simply ask for TodoDbContext, where cancellation comes from, and how every request gets consistent error behavior.

Finish line: after this, stop studying broadly. Build the next feature you care about and look up C#/.NET details as they arise.

1. Read your existing handler as framework binding

app.MapPost("/todos", async (
    CreateTodoRequest request,
    TodoDbContext db,
    CancellationToken ct) =>
{
    // ...
});

ASP.NET Core recognizes each parameter by its type and route/body context. It deserializes the request body into request, resolves db from dependency injection, and supplies ct from the active HTTP request. See the request-shape reference.

builder.Services.AddDbContext<TodoDbContext>(...) registers the context as a scoped service: one context per request. Never share a DbContext across concurrent work, and always immediately await EF Core async calls.

2. Add consistent error responses

Add this before var app = builder.Build();:

builder.Services.AddProblemDetails();

Then add this immediately after var app = builder.Build();, before every Map... call:

app.UseExceptionHandler();
app.UseStatusCodePages();

app.Use(async (context, next) =>
{
    context.Response.Headers["X-Request-Id"] = context.TraceIdentifier;
    await next(context);
});
PieceEffect
AddProblemDetailsRegisters RFC 7807-style JSON error responses.
UseExceptionHandlerConverts unexpected exceptions from later pipeline stages into a controlled 500 response.
UseStatusCodePagesProduces a problem-details body for otherwise empty 4xx/5xx responses, including route misses.
Request-ID middlewareReturns a correlation ID clients can provide when reporting an error.

3. Verify the pipeline

Restart the API and run:

curl -i http://localhost:5229/health
curl -i http://localhost:5229/no-such-route

Both responses should include X-Request-Id. The unknown route should be a JSON problem-details response with 404, not an empty response.

4. Exercise: test an unexpected error, then remove the route

Temporarily add this endpoint after the middleware:

app.MapGet("/debug/throw", () =>
    throw new InvalidOperationException("Intentional teaching error"));

Call it with:

curl -i -H 'Accept: application/json' http://localhost:5229/debug/throw

You should receive 500 with JSON problem details. Delete the temporary endpoint afterward. Do not expose debug-throw endpoints in a real API.
