Turn C# into an HTTP server.

You already know HTTP. The new material is ASP.NET Core’s compact route-to-handler model and how dependency setup becomes an application pipeline.

Mission connection: this is the shell we will later connect to PostgreSQL. For now, make two routes you can call with curl.

1. Create the API project

cd /home/rk/dev/dotnet-playground/api
dotnet new web -n TodoApi
cd TodoApi
dotnet run

The terminal prints listening URLs. Keep this process running and use the http://localhost:… URL it reports; use HTTP for this first local exercise.

2. Read the template as a lifecycle

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello World!");

app.Run();
LineJobGo comparison
CreateBuilderCollect configuration, logging, and dependency registrations.Constructing application dependencies before starting the server.
BuildProduces the application and its request pipeline.Assembling a router plus middleware chain.
MapGetMatches GET requests and invokes a handler.mux.HandleFunc, with request binding handled by the framework.
RunStarts Kestrel and blocks until shutdown.http.ListenAndServe.

3. Replace the route with two routes

Replace the template’s single MapGet line with:

app.MapGet("/health", () => Results.Ok(new { status = "ok" }));

app.MapGet("/greet/{name}", (string name) =>
    Results.Ok(new { message = $"Hello, {name}!" }));

The anonymous objects become JSON. The name parameter binds from {name} in the route template. This is convention plus type information—not reflection magic you need to wire by hand.

4. Exercise: verify the HTTP contract

Use the actual port reported by dotnet run:

curl -i http://localhost:PORT/health
curl -i http://localhost:PORT/greet/Ada

Expected bodies:

{"status":"ok"}
{"message":"Hello, Ada!"}
Important: endpoint handlers may be synchronous like these, or async and return Task<IResult>. We will use that shape when database I/O arrives. Do not make a handler async just because it can be.
